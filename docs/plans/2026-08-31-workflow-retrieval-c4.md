## 5. 工作包 B：提高检索精度

### B1. 先冻结评测，不先调权重

- 建立独立的本地查询/相关工作标注集，至少 120 条，其中至少 40 条无匹配或干扰负例；来源覆盖多个项目类型，不能只在本项目 W001 上拟合。
- 覆盖精确 ID/路径/符号、中文改写、英文改写、跨语言 aliases、同模块不同目标、否定/切题、陌生主题、多个并列目标、无主题续接、带主题续接、歧义、旧任务与活动任务。
- 标注期望 workId 集合及是否允许自动读取；训练/调参集与保留集按任务/改写家族拆分，避免同一问法模板泄漏。
- 先记录当前基线并冻结保留集；不要看保留集失败后反向改参数再把同一集当独立验收。

### B2. 修正证据覆盖与中文计分

- 保留完整的有效查询主题信息：同时报告完整查询和词表内命中，不能将“词表内覆盖率”称为完整主题覆盖率。
- 陌生实质主题不能被静默丢弃；同时避免把长礼貌语或背景叙述作为分母，造成所有长问题都无法召回。
- n-gram 仍可召回，但重叠片段不得冒充多个独立语义证据；按词段/标识符/短语组计算可靠性特征。
- 通用词、低区分度词的组合不能单独达到自动读取门槛；不通过无限扩大停用词表压制真实需求。
- 优先利用现有 title/summary/modules/aliases，aliases 表达具体对象、行为和问题，不扩展成整段聊天摘要。

### B3. 处理请求意图与明确排除

- 区分目标提及与明确排除，例如“不要继续 W001，处理 W002”；排除约束在确定性与词法路由中一致执行。
- 使用有边界、可测试的明确句式；一般否定故障描述如“电机不能启动”不能被当作排除电机。
- 模糊否定、引用或多意图无法可靠解释时保留候选并标明歧义，不声称理解了全部自然语言。
- “继续上次”无具体主题时保留既有最近工作策略；包含具体主题但主题不匹配时不兜底到无关工作。
- 不为 Hook 增加 LLM、网络或付费重排。自动路由保持确定性、可解释；主会话对歧义候选做必要的语义核对。

### B4. 分离可靠结果、歧义候选与无匹配

- 完整 CLI 匹配继续返回全部可靠工作，不以固定 top-1 或未披露的数量上限隐藏多目标结果。
- 增加只读诊断入口，显示命中依据、主题覆盖、歧义/拒绝原因；评分不标成概率。
- Hook 对可靠结果提供简短定位；歧义只提示有待核对的候选，不再把这些候选一律指令化为“读取所有可靠 current”。
- 无可靠结果时允许安静退出；保留显式 ID、路径、符号定位的能力及无模型回退。
- 保留现有字符预算、截断提示、current/revision 去重及历史隔离；同一 revision 的重复召回不会重复注入正文。

### B5. 拟议验收目标

这些是实施前需要冻结的工程目标，不是当前性能声明：

- 精确定位与安全负例全部通过；明确排除不得被较高词法分数覆盖。
- 唯一目标问题的 Top-1 正确率至少 90%；自动读取结果精确率至少 95%。
- 正例自动召回率至少 85%，防止通过全部拒答虚增精确率；无匹配负例误召回率不高于 5%。
- 歧义/并列多目标按集合与正确保留歧义计分，不强迫唯一答案；关键类别不能被总体平均分掩盖。
- 10/100/1000 工作规模下维持现有 Hook 超时门槛；1000 项整体路径不得超过既有 5 秒测试预算。记录本机基线和耗时分布。
- 对阈值未达标的情况明确失败或调整后重新独立评测，不宣称 BM25 能覆盖所有无词面重合的语义改写。

改动面：`src/application/bm25.ts`、`handoffs.ts`、必要的结果类型/CLI 诊断、`src/hooks/user-prompt-submit.ts`；对应 bm25/matcher/hooks 测试和新增评测夹具。第一阶段不改变持久索引 schema，也不加入 embedding 运行时。

## 6. 工作包 C：跟踪 C4 四维状态

### C1. 沿用现有状态，不压成一个总状态

| 字段 | 合法值 |
|---|---|
| baselineStatus | pending-confirmation / confirmed |
| designStatus | proposed / approved |
| implementationStatus | not-started / partial / implemented |
| verificationStatus | not-run / pass / fail / blocked |

继续执行既有合法组合与失效规则。软件实现存在而设备 blocked 是有效中间状态；pass 必须注明验证范围、目标构建和证据，不能推出可发布。

### C2. 源状态与观察快照分开

- C4 metadata 是架构技能维护的声明来源；代码、配置、用户决定和测试证据负责支持声明，模型不能覆盖相反事实。
- Project Context 不复制 DSL、不解析 LikeC4 内部 AST、不建立第二个权威状态库。
- 在符合 handoff 准入时，用现有 currentState/decisionsAndConstraints/verification/evidence 章节记录固定可读的 C4 状态快照；沿用 workId/revision，不增加另一套生命周期文件或持久 schema。
- 快照包含目标项目、架构域/变化 ID、根 FQN、模型和变化路径、四维状态、观察时间、源码指纹、相关验证范围/产物定位、已有 plan/work ID、待办和阻塞。
- 指纹覆盖该架构域的配置、specification、正式模型和活动变化等影响输入，而不是仅一个 changes 文件；生成图片、站点与布局缓存不作为权威输入。
- 一期是 Skill 驱动的可读状态查询与跨任务恢复，不承诺自动看板、实时状态同步或机器级审批门禁。

### C3. 何时更新、何时判旧

- 架构技能完成确认、批准、实现阶段、验证、退回 Review 或关闭时，先更新/验证 C4，再按现有准入规则创建或更新同目标 handoff；无跨任务需要时只维护 C4。
- 新任务恢复、用户查询 C4 状态、或继续依赖旧验证结论前，先检查定位和相关指纹；发生变化、文件缺失、来源冲突或证据无法核对时，报告 stale/needs-check，不能沿用快照的 pass。
- stale/needs-check 是观察质量，不扩展 C4 的业务状态枚举；Project Context 不擅自改 C4 或批准声明。
- 合法的状态字段更新也会改变文件 hash；受控更新后重新生成观察快照。hash 只帮助发现变化，不自动判断变化是否实质，更不是用户批准的签名。
- 设计实质变化需重新 Review；软件或测试证据变化时重新确认适用验证。未提供足够证据指纹时只能报告“模型声明 pass，当前证据未核对”。
- Git 删除活动变化文件不等于完成。正常关闭需已有状态/验证和明确关闭证据；通过提交定位或 handoff 历史保留来源。异常缺失按未知处理，不标 completed。
- 无 Project Context 初始化时，C4 自身仍能跟踪；不隐式初始化。LikeC4 不可用时可报告最后观察值及过期/未核实标记，不能宣称实时核验成功。
- Hook 不遍历所有 C4、不读取全量模型，不在每次提示中重复这些状态。

改动面：embedded-architecture-review 主文件及新增状态参考；Project Context 的 handoff/plan 参考、必要的生成指引与文档；增加场景验收。现有 CLI 写入 current handoff，不增加通用 artifact registry 或计划追加 API。

### 冻结指标定义

- 每条查询分别保存 relevantIds、autoReadAllowed、expectedDisposition 和 split；候选集合（含 aliases）与标签一同校验 SHA-256。
- 自动精确率：允许自动读取结果中的正确工作项数 / 全部自动输出工作项数。对 autoReadAllowed=false 的查询自动输出任何项均计错误。
- 自动召回率：autoReadAllowed=true 查询中正确自动输出工作项总数 / 这些查询的 relevantIds 总数；禁止自动读取的歧义样本不进入分母。
- Top-1：自动读取被允许且仅有一个相关工作的正例中，第一条结果正确的查询占比；不返回结果算失败。
- 多目标完整率：相关集合不少于两个且允许自动读取的查询中，返回集合与 relevantIds 完全一致的占比；关键多目标用例必须全部通过。
- 无匹配误召回率：relevantIds 为空的查询中，出现任何自动结果的查询占比。歧义保留率独立计算，要求不自动读取且候选集合覆盖相关集合。
- 冻结手算例：G={A,B} 仅返回 A，精确率=1、召回率=1/2、完整率=0；歧义 G={A,B} 仅返回候选，自动召回分母为0、候选覆盖=1；G={A} 自动返回 A 和干扰 B，精确率=1/2、召回率=1、Top-1 按首项判断。
